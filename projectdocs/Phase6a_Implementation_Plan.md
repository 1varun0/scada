### 1.2 Physics False Positives Breakdown
Breakdown of the 18,046 false positives generated by the physics engine:
- **A1/A2 Physics FPs:** 0
- **A3 (DoS) FPs:** 7,561
- **A4 (Auth Misuse) FPs:** 10,485

**Root Causes:**
- **A3 (DoS)**: The stored DoS windows in the dataset are internally inconsistent: during the DoS, reported level is held, flows are zeroed, and actuator states are recorded as 0 (fail-safe); after the DoS ends, the reported level jumps up to the uninterrupted-fill trajectory (about 1.5 mm/s x duration: 3 cm to 17 cm) within 1 to 5 ticks (A3_010: 1.022 to 1.189 in one tick; A3_001 converges in about 5 ticks). The digital twin, which open-loop integrates the reported zero flows, falls behind by $\approx \text{duration} \times \text{net fill rate}$ and cannot follow that jump, remaining permanently offset and triggering 7,561 false positive ticks.
- **A4 (Auth Misuse)**: At the exact end of the attack window (e.g., `t=301`), the dataset generator stitched the state back to the nominal uncompromised trajectory, causing the observed level to abruptly jump by 0.3 meters in 1 second. The twin expects physical continuity and does not teleport, creating a persistent residual > `tau_p`.

### 1.3 Twin Tracking Error, Dataset Noise Spec & FDI Calibration
- **Dataset Noise Spec:** The clamp $\max(0, Q + \text{noise})$ is part of the dataset noise specification. In long runs (>25–30 minutes), this one-sided truncation integrates into a positive drift that can exceed $\tau_p = 0.035\text{ m}$. In short horizons (1,000 s), this bias remains within bounds. For extended live demonstrations, zero-mean Gaussian noise is used as an intentional deviation.
- **Dataset FDI Bias Calibration:** The dataset FDI bias ranges from $+0.05\text{ m}$ to $+0.20\text{ m}$ (sensor noise is $\sigma_H = 0.005\text{ m}$ / 5 mm). The dataset FDI bias shifts the level reading by 5–20 cm; while this triggers the physics detector ($\tau_p = 0.035\text{ m}$), within the 1,000 s dataset scenario duration it causes no physical hazard because the controller hysteresis band is 0.4 m ($0.8\text{ m} \to 1.2\text{ m}$). For Phase 6a overflow prevention demonstrations, large or ramped FDI bias over extended durations (15–30 min) is required to drive the physical tank to physical overflow ($H > 2.5\text{ m}$).

### 1.4 Policy Check Consistency
- `default_valve_pct` is correctly `50.0` across `parameters.py` and `config.yaml`.
- **Policy v2 Exemption:** The in-deadband pump toggle was refined after inspecting attack data: safe valve position ($0.0\%$) is only exempted if `pump_command == 0` (the actual fail-safe state).
- **StreamingIDS Patch:** `StreamingIDS` accepts `policy_version` via configuration (defaults to `v1` for equivalence tests, `v2` for live operations).
- **Live Soak Validation (v2):** Policy v2 fired 0 times on the 30-minute normal live run.

## 3. Per-Tick Control Flow (GatewayCore)

The control logic runs in `GatewayCore.step()`. The source for this tick's control comes from the *previous* tick's verdict (harm window = N-of-W flags + 1 tick).

1. **Alert Manager & Mode Read:** Gateway reads `self.mode` and checks `alert_manager.state == cfg.prevention.trigger_state` ("CRITICAL").
2. **Action Selection (Prevention Mode Only):**
   - If `mode == "prevention"` and alert state is `CRITICAL`:
     - If any engine in `cfg.prevention.takeover_engines` (e.g. `physics`) is in `engines_firing` (FDI), set `action_taken = "twin_takeover"`.
     - *Hand-back logic:* If no anomaly for `clean_ticks` and `abs(h_obs - h_twin) < handback_tolerance_m`, and `auto_handback=True` (for the harness) or operator acks (for Live UI), revert to `sensor`.
3. **Level Source Choice:**
   - If `action_taken == "twin_takeover"`, `active_level = ids.get_twin_estimate()`.
   - Else, `active_level = pkt.level_m` (from the *current* sense).
4. **Command Reply:** `controller.step(active_level)` is called. The resulting commands are forwarded to `plant.advance()`.
5. **IDS Update:** `ids.update(pkt)` is called *after* commands are generated to evaluate the current packet and update states for the *next* tick.

## 4. A/B Harness Design (`experiments/run_comparison.py`)

- **Transport:** In-process direct function calls (no Flask/HTTP). Runs at CPU maximum speed.
- **Attacks (Phase 6a scope):** 
  - FDI Downward (spoof level lower -> forces pump ON -> overflow).
  - FDI Upward (spoof level higher -> forces pump OFF -> dry run).
  - Stealthy Ramp (spoof slow drift).
- **Seeds & Timing:** 10 random seeds. The exact same seed is run twice: once for `Monitor` and once for `Prevention`.
- **Attack Calibration:** 
  - Time-to-overflow for an FDI downward (level lower) takes roughly 15 to 25 minutes. 
  - The harness simulation will run for at least 30 simulated minutes to guarantee overflow in Monitor mode, proving Prevention stops it.
- **Metrics Recorded:** Peak/Min true level, Overflow events/ticks, Dry-run events/ticks, False mitigations, Time spent in estimator control.

- *Checkpoint:* Unit test `test_gateway_mode`, `test_handback_rules`, and `test_twin_control_stability`.

**Step 2b: DoS Gap Re-Seed Rule & Physical Rate Bounds (Completed)**
- Implement `dos_gap_rule` in `StreamingIDS` (default False for Phase 2 equivalence, True passed explicitly in `GatewayCore`).
- After a gap of $G$ ticks with `received=False`, collect $K=5$ consecutive valid post-gap readings, require $\text{std} \le \text{max\_std\_m} = 0.03\text{ m}$, and check physical rate bounds: $|m - h_{twin}| \le v_{max} \cdot G \cdot dt + 3\sigma_{sensor}$, where $v_{max} = \max(q_{in,max}/A, C_v \sqrt{h_{max}}/A) = 0.003162\text{ m/s}$ and $\sigma_{sensor} = 0.005\text{ m}$.
- Add `gap_collect_timeout_ticks` (default 20): on timeout, refuse re-seed, release suppression, log warning.
- *Limitation*: A spoof within $v_{max} \cdot G \cdot dt + 3\sigma_{sensor}$ after a gap is adopted by the twin; the command-driven shadow estimator in Phase 6c is the structural fix.
- *Checkpoint:* Unit tests for gap-free equivalence, suppression timeout recovery, mode independence with rule ON, and batch replay of 15 A3 scenarios.

**Step 3: A/B Comparison Harness**
- Write `experiments/run_comparison.py`.
- *Checkpoint:* Run A/B harness for 30 simulated minutes and verify output CSV proves FDI prevention.
