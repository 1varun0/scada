### 1.2 Physics False Positives Breakdown
Breakdown of the 18,046 false positives generated by the physics engine:
- **A1/A2 Physics FPs:** 0
- **A3 (DoS) FPs:** 7,561
- **A4 (Auth Misuse) FPs:** 10,485

**Causes (Feature, not a Bug for A3/A4):**
- **A3 (DoS)**: The network drops packet delivery, so the dataset batch rows carry *stale* flows (the last flow before network interruption). The twin integrates these stale/zero flows, but the actual simulation plant kept moving, creating a divergence.
- **A4 (Auth Misuse)**: At the exact end of the attack window (e.g., `t=301`), the MATLAB dataset generator artificially stitched the state back to the nominal uncompromised trajectory, causing the observed level to physically teleport by 0.3 meters in 1 second. The twin expects continuity and refuses to teleport, creating a permanent residual > `tau_p`. Most of the 21% FPR is a dataset artifact.

### 1.3 Twin Tracking Error & Noise Bias Fix
- **Live Run Twin Drift Bias:** The previous 0.04m error was caused by a systematic bias in `simulator/noise.py`, which used `max(0.0, noisy_flow)`. Because it clipped the Gaussian noise at zero when the pump was off, the Twin integrated a net positive flow (~0.08L/s), resulting in a linear drift.
- **After removing the zero-clamp bias:**
  - Max error over 30-minute Live Run (1,800 ticks) is now **0.022 m**.
  - This is strictly below the `tau_p = 0.035` threshold. No `tau_p` tuning is required.
  - *Trade-off:* By accepting unbiased noise, a slow FDI ramp can hide slightly longer within the noise band, but Twin control remains stable within the 0.4m hysteresis band.

### 1.4 Policy Check Consistency
- `default_valve_pct` is correctly `50.0` across `parameters.py` and `config.yaml`.
- **Policy v2 Exemption Fix:** The in-deadband pump toggle was missed because the attacker sent `valve=0.0` (safe position). The `evaluate_v2` logic was updated to only allow `0.0` if `pump_command == 0` (the actual fail-safe state).
- **StreamingIDS Patch:** `StreamingIDS` now accepts `policy_version` via configuration (defaults to `v1` for equivalence tests).
- **Live Soak Validation (v2):** Policy v2 fired 0 times on the 30-minute normal live run.

## 3. Per-Tick Control Flow (GatewayCore)

The control logic runs in `GatewayCore.step()`. The source for this tick's control comes from the *previous* tick's verdict (harm window = N-of-W flags + 1 tick).

1. **Alert Manager & Mode Read:** Gateway reads `self.mode` and checks `alert_manager.is_critical()`.
2. **Action Selection (Prevention Mode Only):**
   - If `mode == "prevention"` and `is_critical`:
     - If `physics` is in `engines_firing` (FDI), set `action_taken = "twin_takeover"`.
     - *Hand-back logic:* If no anomaly for `clean_ticks` and `abs(h_obs - h_twin) < handback_tolerance_m`, and `auto_handback=True` (for the harness) or operator acks (for Live UI), revert to `sensor`.
3. **Level Source Choice:**
   - If `action_taken == "twin_takeover"`, `active_level = ids.get_twin_estimate()`.
   - Else, `active_level = pkt.level_m` (from the *current* sense).
4. **Command Reply:** `controller.step(active_level)` is called. The resulting commands are forwarded to `plant.advance()`.
5. **IDS Update:** `ids.update(pkt)` is called *after* commands are generated to evaluate the current packet and update states for the *next* tick.

## 4. A/B Harness Design (`experiments/run_comparison.py`)

- **Transport:** In-process direct function calls (no Flask/HTTP). Runs at CPU maximum speed.
- **Attacks (Phase 6a scope):** 
  - FDI Downward (spoof level lower -> forces pump ON -> overflow).
  - FDI Upward (spoof level higher -> forces pump OFF -> dry run).
  - Stealthy Ramp (spoof slow drift).
- **Seeds & Timing:** 10 random seeds. The exact same seed is run twice: once for `Monitor` and once for `Prevention`.
- **Attack Calibration:** 
  - Time-to-overflow for an FDI downward (level lower) takes roughly 15 to 25 minutes. 
  - The harness simulation will run for at least 30 simulated minutes to guarantee overflow in Monitor mode, proving Prevention stops it.
- **Metrics Recorded:** Peak/Min true level, Overflow events/ticks, Dry-run events/ticks, False mitigations, Time spent in estimator control.
